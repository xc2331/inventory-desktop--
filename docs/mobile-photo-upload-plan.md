# 手机拍照上传物品照片方案讨论

> 当前阶段：方案选型，暂不实现代码。

## 1. 目标

让用户在电脑端录入物品时，能用手机快速拍摄并上传该物品照片，避免先把照片传到电脑再选择文件的繁琐流程。

约束：
- 数据优先本地，避免强制依赖云端。
- 电脑端已有一个本地 HTTP API（`127.0.0.1:3001`）。
- 手机和电脑需要在同一网络下才能直接通信（除非做额外中转）。

## 2. 可选方案对比

| 方案 | 原理 | 优点 | 缺点 | 推荐度 |
|---|---|---|---|---|
| A. 局域网临时上传页 + 二维码 | 桌面端临时开启一个上传会话，生成二维码；手机扫码后打开上传页，选图/拍照上传，电脑端接收并关联到当前正在编辑的物品。 | 不需要单独开发手机 App；复用现有 HTTP 服务；端到端本地。 | 需要手机和电脑在同一局域网；要处理 IP 获取、会话过期、端口冲突。 | **推荐** |
| B. 手机 PWA 网页长期配对 | 手机端保存一个「配对桌面」的 PWA 页面，类似远程遥控器，可随时选图上传。 | 体验接近原生；一次配对多次使用。 | 仍然依赖局域网；需要维护配对码和心跳。 | 中 |
| C. 第三方云图床 / 文件中转 | 手机上传到图床/网盘，电脑端粘贴 URL 或自动拉取。 | 不限网络，实现快。 | 需要第三方服务，违背本地优先；隐私和稳定性不可控。 | 低 |
| D. 剪贴板 / 文件共享 | 手机通过系统级共享（AirDrop、微信文件传输等）把图片发到电脑，再拖拽进表单。 | 零开发。 | 流程不连贯，依赖外部工具，不符合「更方便」的目标。 | 低 |

## 3. 推荐方案 A 的详细流程

### 3.1 用户视角

1. 在电脑端打开「添加/编辑物品」表单，点击「通过手机上传照片」。
2. 桌面端弹出一个二维码窗口，并显示本次上传的配对码（如 6 位数字）。
3. 手机扫码（或手动输入配对码），浏览器打开一个极简上传页。
4. 手机拍照或从相册选择照片，点击上传。
5. 电脑端实时显示已收到照片，并自动填充到当前表单的图片字段；用户继续填写其他信息并保存。

### 3.2 技术流程

```
电脑端（Electron）                          手机端（浏览器）
    |                                            |
    |  1. POST /api/upload-sessions              |
    |     创建上传会话（sessionId、过期时间）      |
    |-------------------------------------------->|
    |     返回 {sessionId, qrUrl, uploadUrl}     |
    |                                            |
    |  2. 生成二维码（qrUrl）                     |
    |  3. 轮询 GET /api/upload-sessions/:id       |
    |                                            | 4. 扫码打开 uploadUrl
    |                                            | 5. 选择图片，POST 到 /api/upload-sessions/:id
    |  6. 收到图片，回调到 ItemForm               |    （multipart/form-data）
```

### 3.3 二维码内容

二维码应包含一个**手机可直接访问的 URL**：

```
http://<电脑局域网IP>:3002/upload/<sessionId>
```

- 如果 Agent API 已开启「局域网模式」，可直接使用现有端口 `3001`。
- 为安全和隔离，也可以单独起一个临时上传服务器（如 `3002`），仅在该会话期间监听 `0.0.0.0`。
- 会话 ID 使用随机 UUID，15 分钟内过期。

### 3.4 需要新增的底层功能

| 模块 | 改动点 |
|---|---|
| `electron/api-server.js` | 新增 `POST /api/upload-sessions`、`GET /api/upload-sessions/:id`、文件接收（`multipart/form-data`）。 |
| 网络发现 | 获取本机局域网 IP，生成二维码。可用 `os.networkInterfaces()` 过滤内网地址。 |
| 前端 | `ItemForm` 增加「手机上传」按钮和二维码弹窗；上传完成后回填 `photo` 字段。 |
| 文件存储 | 上传的图片存到数据目录下的 `photos/<itemId>/` 或临时目录，避免跨盘路径问题。 |
| 安全 | 会话过期、Token 校验、文件类型/大小限制（仅图片，单张 ≤ 10MB）。 |

### 3.5 安全与隐私

- 不上传到云端，图片仅在局域网内传输。
- 上传会话 15 分钟过期，过期后 URL 失效。
- 如果用户未开启局域网模式，默认仍监听 `127.0.0.1`，此时手机无法扫码访问；可提示用户先开启局域网模式，或启动临时上传服务器。
- 允许用户随时在设置中关闭上传功能。

## 4. 后续实现建议步骤

1. 在 `electron/api-server.js` 中实现上传会话 API 和文件接收。
2. 在 `electron/main.js` 中增加获取局域网 IP 的辅助函数。
3. 开发一个极简的二维码弹窗组件 `PhotoUploadQRModal.jsx`。
4. 在 `ItemForm.jsx` 中增加「手机上传」入口，上传成功后回填图片路径。
5. 测试同一 Wi-Fi 下手机扫码、拍照上传、超时关闭等边界情况。

## 5. 不实现的原因

当前迭代优先完成「关闭行为设置」「位置推断」等更影响日常使用的功能。手机拍照上传涉及网络发现、文件上传、手机端页面等独立模块，建议作为下一个独立迭代单独开发。
